# BDO-AIO v2.4.2 - Catch a rolled-back client version before it wipes your mods

A maintenance release. No slider values, packs, or pipeline behaviour changed.

## The bug this fixes

Mods reverted on their own and the game reported corrupted files. Nothing was corrupt.

`pad00000.meta` carries the client version as a `uint32` at offset 0 - PartCutGen prints
it as `Meta version:`, and the launcher reads it to decide whether the client is up to
date. On a live NA client the header came out of an inject run saying **3412** when the
installed client was **3418**. The launcher concluded the client had rolled back six
versions, re-downloaded `3413..3418.PAP` (about 1 GB), and replaced `pad00000.meta` -
destroying the injection and stranding 1.65 GB of `PAD6xxxx.PAZ` archives.

Evidence is the launcher's own `update.log`: the client read 3418 continuously for days,
then 3412 fifty-one seconds after Meta Injector rewrote the meta.

PartCutGen was suspected and is **not** at fault. Against a clean meta it reports
`Meta file status: Clean` and generates its exclusions normally.

## What changed

- Meta Injector runs record the client version **before** injecting and re-check it
  afterwards. On a mismatch the AIO says **DO NOT LAUNCH** and points at restore.
- New `vanilla_restore.py verify`:
  - `--expect-version N` fails when the header version changed across a run.
  - Without it, still proves every block resolves inside an archive that exists - the
    actual definition of the corrupted-data the client reports.
- `restore` refuses a snapshot whose `meta_version` differs from the live meta (exit 5),
  because restoring an older snapshot causes the same rollback by a different route.
- `backup` records `meta_version`, and judges the meta instead of refusing whenever a
  `BDO_AIO_INJECT` folder happens to exist.
- `scan` reports the client version and no longer prints `INJECTED` when the meta
  references zero injected archives.
- Startup warns when the client version changed since your last inject.
- Removed the old "restore vanilla first if the launcher walls on a patch" advice. With
  a snapshot from an older client, that advice caused the very problem it promised to
  avoid.

## After a game patch

A patch replaces `pad00000.meta` outright, so any earlier injection is already gone and
its archives are orphaned. Correct order:

1. Let the launcher finish patching and start the game once.
2. Re-snapshot vanilla on the new client version.
3. Re-apply AIO, then PartCutGen, then Meta Injector.

## Validation

- All Python suites and PowerShell launcher/config suites pass.
- `verify` exercised both ways on a live client: passes at the true version, fails on a
  simulated regression.
- New `test_config_roundtrip.ps1` proves every seeded config key is persisted and
  migrated. It was written after `lastMetaVersion` was found being silently dropped by
  `Save-Config`, and it fails if that regresses.
- Automated checks do not prove in-game appearance.
